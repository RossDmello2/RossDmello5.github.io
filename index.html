03 · Philosophy

The model is 10% of the system.
I engineer the other 90%.

Below is a live simulation of the canonical workflow shape I build to. Watch the packets: valid data flows through six stages to persistence — malformed data is caught at the validation gate and routed to manual review instead of being confidently automated. This is the whole philosophy, animated.

valid packet → automated malformed packet → manual review persisted · observed
P—01

Prefer null over a confident lie

When extraction confidence is low or a PDF is unreadable, my pipelines emit a manual-review status — never a plausible-looking wrong answer.

P—02

Fail closed

Unknown intent, missing auth, out-of-scope query — the system declines with a structured error instead of improvising across a privacy boundary.

P—03

The contract is the product

JSON-only outputs, schema validation, deterministic error shapes. Downstream systems should never parse prose to find out what happened.

P—04

Respect the rate limit

Batching, wait-steps, key rotation, retry with backoff. An automation that amplifies provider calls under failure is a cost incident waiting to happen.

P—05

Secrets never ride in exports

Credentials live in credential stores and environment variables. I learned this the hard way once — and turned it into a standard: rotate, redact, re-export, document.

P—06

Observe everything

Execution IDs, structured logs, health checks. If a workflow can’t explain what it did last night, it isn’t done.
